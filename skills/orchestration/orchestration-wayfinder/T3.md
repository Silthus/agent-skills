# Orchestration Wayfinder — T3 Code threads

Read this addendum when the conductor runs inside T3 Code, together with the runtime addendum. Every **HITL lane** gets its own T3 thread in the sidebar: grilling, prototype, spec, and a HITL `task`. So does every `implement` ticket, a stack or a standalone pull request, because only the thread that owns a pull request watches it. The human switches to the thread and works the ticket there, while the conductor keeps the rest of the frontier moving.

## Every wake

Run this checklist first on every conductor wake, a hold's end included:

1. **After a compaction**, load the deferred tools the hold and the lanes need before anything else (in Claude Code, `ToolSearch` for `Monitor`, `TaskStop`, and every T3 tool this file names), reread the [`t3-kickoff`](../t3-kickoff/SKILL.md) skill and the **lane file**, and run **Recovery**.
2. Run one lanes command: `fleet lanes <map URL>` when the `fleet` CLI is available, otherwise the `kickoff status` check under **Wake**. Act on each line it prints per **Wake**.
3. List pending requests with `t3_pending_request_list`, and cue each new one on a thread in the lane file per `blocked` under **Wake**.
4. An **empty wake**, with no notice and nothing found in steps 2 and 3, is those commands and a re-armed hold, with no message.

The **lane file**, `$(git rev-parse --git-common-dir)/wayfinder/<map>/lanes.md` in the conductor's checkout, lists every open lane: its ticket, type, full thread id, or task id and child thread id, and title. Update it with every locator you record, drop a lane when its ticket closes, and rebuild it from the tickets' locator comments when it is missing. A compaction summary carries each open lane's full ids and the hold's state with its task id.

AFK work that opens no pull request, meaning research and AFK `task` tickets, dispatches through the runtime addendum as T3 child tasks: `delegate_task` with `mode: async`. A child task that writes files, commits, or checks out a branch passes `isolation: "worktree"`. A child task survives a conductor restart and wakes the conductor when its turn ends, so the conductor ends its turn instead of polling, then reads the result with `task_status`. Every child task prompt says to push its branch, when it has one, before it parks. Record the locator on the ticket immediately:

```md
<!-- orchestration-wayfinder-dispatch -->

Runtime: T3 Code
Task: <taskId>
Child thread: <childThreadId>
```

A HITL or stack lane runs as a thread because T3 keeps the conductor on the Working shelf while any child task it started is live. A park inside a child task waits where the human never looks. An AFK child that parks anyway gets a successor thread, per **Wake**.

The thread status and stop commands come from the [`t3-kickoff`](../t3-kickoff/SKILL.md) skill. Read it before the first thread. Below, `kickoff` means `bun <t3-kickoff skill directory>/scripts/kickoff.ts`.

## Cast

A T3 thread runs its model natively through T3. It is not a provider bridge, so the retired-cast rule in [`SKILL.md`](SKILL.md) does not apply to the thread's own model.

Follow **Casting** in [`SKILL.md`](SKILL.md) to choose the worker's model, then select the provider offering it. Pass both in `modelSelection`, with the effort in its `options`, so the conductor's own model does not replace the selection.

When the `fleet` CLI is available (on `PATH` or at `~/dev/fleet/fleet`), read `fleet availability`, the live-quota report all maps share, before a dispatch; without it, keep the runtime's own provider checks. Defer a family reported as `exhausted`, and keep the user's chosen model. A family's lanes are `lanes.claude` for `claude-*` models and `lanes.codex` for `gpt-*` models. When the report has `lanes`, dispatch a family's frontier only up to its lanes in live workers, and `0` defers the family. Without `lanes`, `unknown` requires the normal live check, and each family runs at most 2. A live worker is a thread or child task with a running turn, or one a usage limit stopped, since the Fleet hub may resume it. This cap replaces any concurrency note from the map's **Notes** or another thread. Dispatch up to the cap at each wake.

## Conductor address

Before the first thread, get the conductor's thread id and title from `t3_thread_configuration` without a `threadId`. Write them as the `Conductor` line of the **Stacks board** in [`SKILL.md`](SKILL.md). A new conductor after a handoff or resume updates this line before it does anything else. Workers read the line when they notify, so a conductor change never strands a thread. Child tasks are different: the task tools answer only the thread that started the task. Before a handoff, move each parked child to a successor thread per **Wake**, dispatch no new child task, and hand off when the last one ends.

## Start a thread

1. Render the worker prompt to a file per [`LANE.md`](LANE.md). Its template adds the ticket type's terminal and **Notify and settle** below, and tells the worker that the human talks to it in this thread.
2. Launch it with `t3_thread_launch` in the code repo's T3 project, per **Map tracker** in [`SKILL.md`](SKILL.md): `title` `<type> #<id>: <ticket title>`, `modelSelection` per **Cast**, `workspaceStrategy` `{ type: "worktree", baseRef: <base> }`, and the prompt as `message`. `<base>` is the default branch, or for a successor the branch its predecessor pushed. Pass `branch` when the ticket has a fixed one, such as `prototype/<name>`. Done when it returns the thread id. After an error or a lost reply, look for the thread with `t3_thread_list` before launching again.
3. Record the locator on the ticket immediately:

   ```md
   <!-- orchestration-wayfinder-dispatch -->

   Runtime: T3 Code
   Thread: <threadId>
   Title: <thread title>
   ```

4. For an `implement` ticket, set its board row's Thread to the thread's link and its State to `building`.
5. Grilling only: cue the human once with the thread title, because grilling is live from the first turn. Record `<!-- orchestration-wayfinder-cue:t3:<threadId> -->` on the ticket.

Arm no waiter. The thread reports to the conductor itself. End the turn per **Wait out of the inbox** below.

## Terminals

**Grilling.** The worker grills the human live in the thread with the `grilling` and `domain-modeling` skills. When the tree is exhausted, it posts the durable handoff comment, closes the ticket, notifies and settles, and ends its turn with a one-line summary.

**Prototype.** The worker builds the prototype with the `prototype` skill, or `architecture` for an architecture prototype, on its `prototype/<name>` branch in its AFK stretch, then parks: the park comment, `wayfinder:awaiting-human`, a park notice, and a thread message. For a prototype from the `prototype` skill, the message carries the link the `prototype` skill hands over and names the one question it answers. For an architecture prototype, the pending question is its first `architecture` round, and both the message and the park comment are that round in full, per **Rounds** and **Render the diagram** in `architecture`. Its branch stays empty until capture, so until then the thread message links only the ticket and the ticket comment has no links line. A `prototype` skill preview is a systemd unit outside the thread, so it stays up through the park, up to `share-preview`'s 24-hour limit on a leased box; the **lane rules** in [`LANE.md`](LANE.md) cover what runs in the thread. When a reply comes after that limit, restart the preview per `share-preview` before iterating. Each human reply is feedback. A `prototype` skill worker iterates, pushes, and ends its turn. An architecture worker posts its next round in the thread and as a new ticket comment, ends its turn, and pushes its branch at capture. The human's explicit acceptance is the only resolution. On acceptance, the worker pushes the branch, posts the durable handoff with the decision, the branch pointer, and, for a UI prototype, its element checklist per the `prototype` skill, removes `wayfinder:awaiting-human`, closes the ticket, and notifies and settles.

**Stack.** The worker follows **Stack thread** in [`SHIP.md`](SHIP.md). It links each pull request with `link_pull_request`, watches them with `watch_pull_request`, and ends its turn while it waits. Before it parks or hands back, it calls `unwatch_pull_request` on each one, so the thread lands in the human's inbox. Its handback is a park per the next terminal. When a reply switches its mode, it removes `wayfinder:awaiting-human` and carries on per **Modes** in [`SHIP.md`](SHIP.md).

**Spec, HITL task, stack parks, and successors.** The worker runs its AFK stretch with its prescribed skill, and a successor continues from its predecessor's park, whose park comment and label already stand. Then it parks: the park comment, `wayfinder:awaiting-human`, a park notice, and a thread message with the pending question and the ticket link. Each human reply answers it: the worker records the decision on the ticket and continues to the next park or to the resolution. On resolution, the worker posts the durable handoff, removes `wayfinder:awaiting-human`, closes the ticket, and notifies and settles.

## Notify and settle

Every worker prompt includes these steps. The worker sends a notice only on a tracker transition, never on an ordinary conversation turn:

- **First park** → after the park is durable, send the conductor `<type> #<id> parked` with `t3_thread_send`, `mode: auto`, to the thread on the map body's `Conductor` line.
- **State change** → a stack thread sends its state notice, per **Stacks board** in [`SKILL.md`](SKILL.md), the same way. For a park, this notice replaces the park notice.
- **Closed** → after the ticket is closed, send the conductor `<type> #<id> closed` the same way. Then call `t3_thread_organize` with `action: settle` and no `threadId`. The thread settles when its turn ends and leaves the human's active list.

If the send fails, the worker still settles. The conductor finds the closed ticket at its next frontier query.

## Wait out of the inbox

While the conductor only waits for its lanes, it must not sit in the human's inbox. T3 keeps a thread on the Working shelf while its turn is over and a monitor, subagent, or background task it started still runs. The conductor uses one **hold** for this: a monitor that only sleeps.

A live child task holds the conductor on the Working shelf the same way, whatever the turn ends with.

The inbox means the human must act. End every conductor turn in one of two ways:

- **Nothing for the human to act on, and a lane is open or a ticket waits on the lane cap** → exactly one hold runs. This includes a turn that ends with a message, such as a status update, a relayed result, or an answer to the human's question: the human reads it on the Working shelf. If no hold runs, start one before the turn ends. In Claude Code, start the Monitor tool with the command `sleep 1800` and `timeout_ms: 1800000`, the Monitor maximum. A Bash `run_in_background` command does not hold the thread.
- **The human must act**: a cue, a question, an orchestration blocker, or done → no hold runs. Stop the hold before the turn ends; in Claude Code, call `TaskStop` with its task id. While an AFK child task is still live, the action waits on the Working shelf until that child ends, within its wall-time cap. When one turn has both a status update and an action, the action decides. A turn that ends while a conductor question or orchestration blocker is still unanswered counts as an action turn.

A hold that ends by itself is a conductor wake: run **Every wake**, then end the turn by the same rule. A hold does not survive a conductor resume. If the runtime has no monitor that outlives the turn, skip the hold; the conductor then waits in the inbox.

## Wake

A notice from a thread is a worker notification. Apply the **Wake law** to the tracker first, then act on the ticket:

- **Closed** → verify the durable handoff and the settle below. The thread retires itself.
- **A state notice** → update that board row and post its map comment, per **Stacks board** in [`SKILL.md`](SKILL.md). Then act on the ticket like any other notice.
- **Open, first `wayfinder:awaiting-human`** → cue the human once with the thread title and the pending question. Record the `t3` cue marker.
- **Open, any other state** → leave the thread alone.

A ticket that parks while its lane is a child task, found on the child's wake or by any tracker query, moves to a thread. Call `task_cancel` on the child whatever `task_status` reports: a parked child can still hold the conductor. Then start a successor per **Start a thread**. Its prompt carries the park comments, the child's `childThreadId` as the transcript, the branch the child pushed, and, for a ticket that runs code, the lease line from **Compute lease** in [`SKILL.md`](SKILL.md) while the map's **Notes** record it, because the successor works in a new worktree. The successor restates the pending question in its thread, without a new park comment or re-asking answered ones, and sends the park notice. Cue that park, not the child's.

Whenever the conductor finds a T3 ticket closed, by notice or by a tracker query, it checks that `t3_thread_list` with `settled: true` lists the thread. If not, the notice or the settle failed: settle the thread with `t3_thread_organize`, `action: settle`, and its `threadId`.

`fleet lanes` prints one line per claimed lane, thread or child task, that is `finished`, `stalled`, `blocked`, or `gone`, and one per devbox that did not answer. Where `task_status` disagrees, trust `fleet lanes`.

- **`finished`** → the lane ended its turn with its ticket open. A stack thread whose board state is `building`, `ready`, `merging`, or `rolling-out` is waiting on its pull request watch: leave it. Otherwise read its result and take the ticket's next step: send the worker what it is missing, or reconcile the lane as orphaned when it left no durable report.
- **`stalled`** → past its cap, stop it with `kickoff stop` or `task_cancel`, mark it orphaned, and reconcile per the lane contract. Under its cap, check it again at the next wake.
- **`blocked`** → the thread after `in thread` waits on a request. Unless the ticket carries `<!-- orchestration-wayfinder-cue:t3-blocked:<that threadId> -->`, cue the human with that thread's title and its request, then record that marker.
- **`gone`** → the `gone: true` case below.
- **A devbox did not answer** → run `fleet lanes` once more. Still silent → its lanes stay unchecked; run the `kickoff status` check below for each open `Thread` lane.

T3 thread lanes have no deadline wake. The human sees a stalled thread in the active list, and the lane contract's health check covers it. The `kickoff status` check runs `kickoff status --thread <threadId>` for each open `Thread` lane whose last durable activity is older than 15 minutes, on every wake without `fleet lanes` and before completion.

- **`state` is `running` and `startedAt` is older than the cap** → `kickoff stop --thread <threadId>`, mark the lane orphaned, and reconcile per the lane contract.
- **`state` is `failed`, its `error` names a usage or rate limit, and its family has lanes above `0`** → the hub's resume sweep passed it over. Settle the thread with `t3_thread_organize`, `action: settle`, and its `threadId`, so the sweep leaves it alone, then mark the lane orphaned and reconcile per the lane contract.
- **`gone: true` with the ticket open** → the human archived or deleted the thread. Mark the lane orphaned, reconcile the ticket per the lane contract, and cue the human once to ask whether to redispatch it.
- **`kickoff status` fails twice** → the T3 server did not answer. Record an orchestration blocker on the map and cue the human once.

## Recovery

T3 threads survive a conductor resume. A ticket whose latest locator says `Runtime: T3 Code` recovers here, not through the runtime addendum.

Update the map body's `Conductor` line first. Then reconcile the tracker. For a `Task` locator, a parked ticket moves to a successor thread per **Wake**. Otherwise read `task_status`: a live task stays; a terminal one whose ticket is still open is orphaned, so reconcile it per the lane contract. Then continue at step 2 of **Every wake**.

An invalidated ticket with a thread: record the invalidation, clear `wayfinder:awaiting-human`, `kickoff stop --thread <threadId>`, then settle the thread with `t3_thread_organize`, `action: settle`, and its `threadId`.
