# Orchestration Wayfinder — T3 Code threads

Read this addendum when the conductor runs inside T3 Code, together with the runtime addendum. Every **HITL lane** gets its own T3 thread in the sidebar: grilling, prototype, spec, a HITL `task`, and `ship`, whose review can park. The human switches to the thread and works the ticket there, while the conductor keeps the rest of the frontier moving.

AFK work, meaning research, implement, and AFK `task` tickets, dispatches through the runtime addendum as T3 child tasks: `delegate_task` with `mode: async`. A child task that writes files, commits, or checks out a branch passes `isolation: "worktree"`. A child task survives a conductor restart and wakes the conductor when its turn ends, so the conductor ends its turn instead of polling, then reads the result with `task_status`. Every child task prompt says to push its branch, when it has one, before it parks. Record the locator on the ticket immediately:

```md
<!-- orchestration-wayfinder-dispatch -->

Runtime: T3 Code
Task: <taskId>
Child thread: <childThreadId>
```

A HITL lane runs as a thread because T3 keeps the conductor on the Working shelf while any child task it started is live. A park inside a child task waits where the human never looks. An AFK child that parks anyway gets a successor thread, per **Wake**.

The thread commands come from the [`t3-kickoff`](../t3-kickoff/SKILL.md) skill. Read it before the first thread. Below, `kickoff` means `bun <t3-kickoff skill directory>/scripts/kickoff.ts`.

## Cast

A T3 thread runs its model natively through T3. It is not a provider bridge, so the retired-cast rule in [`SKILL.md`](SKILL.md) does not apply to the thread's own model.

Follow **Casting** in [`SKILL.md`](SKILL.md) to choose the worker's model, then select the provider offering it. Pass both explicitly to `kickoff` so its CLI defaults do not replace the selection. A wrong slug makes `kickoff` list the offered slugs.

The retired-cast rule still binds every sub-agent the thread spawns, so restate it in the prompt.

When the `fleet` CLI is available (on `PATH` or at `~/dev/fleet/fleet`; use
whichever exists), read `fleet availability` before a dispatch.
All maps use the same shared live-quota report. Defer a family reported as
`exhausted`; do not change the user's chosen model. `unknown` requires the
normal live check rather than assuming capacity or an outage. `t3-kickoff`
enforces a fresh known outage for its launches from the same report. Without the `fleet` CLI, keep the runtime's own provider
checks.

## Conductor address

Before the first thread, get the conductor's thread id from `t3_thread_configuration` without a `threadId`. Record it in the map's **Notes** as `Conductor thread: <threadId>`. A new conductor after a handoff or resume updates this line before it does anything else. Workers read the line when they notify, so a conductor change never strands a thread. Child tasks are different: the task tools answer only the thread that started the task. Before a handoff, move each parked child to a successor thread per **Wake**, dispatch no new child task, and hand off when the last one ends.

## Start a thread

1. Write the worker prompt to a file. It carries everything a runtime worker prompt carries, plus the ticket type's terminal and **Notify and settle** below. It tells the worker that the human talks to it in this thread.
2. Start the thread in the code repo, per **Map tracker** in [`SKILL.md`](SKILL.md). Done when `kickoff` prints the thread id and `turn started`:

   ```sh
   kickoff --project <T3 project of the code repo> --title "<type> #<id>: <ticket title>" \
     --provider <provider> --model <slug> --worktree new --base <base> --prompt-file <file>
   ```

   `<base>` is the default branch; for `ship`, the spec's integration branch; for a successor, the branch its child pushed, or the default branch when it pushed none. The thread works on a scratch `t3code/` branch, so the prompt names the branch the worker pushes to with `git push origin HEAD:<branch>`, which a `ship` worker also passes to `gh pr create --head`.

   Start threads one at a time.

3. Record the locator on the ticket immediately:

   ```md
   <!-- orchestration-wayfinder-dispatch -->

   Runtime: T3 Code
   Thread: <threadId>
   Title: <thread title>
   ```

4. Grilling only: cue the human once with the thread title, because grilling is live from the first turn. Record `<!-- orchestration-wayfinder-cue:t3:<threadId> -->` on the ticket.

Arm no waiter. The thread reports to the conductor itself. End the turn per **Wait out of the inbox** below.

## Terminals

**Grilling.** The worker grills the human live in the thread with the `grilling` and `domain-modeling` skills. When the tree is exhausted, it posts the durable handoff comment, closes the ticket, notifies and settles, and ends its turn with a one-line summary.

**Prototype.** The worker builds the prototype with the `prototype` skill, or `architecture` for an architecture prototype, on its `prototype/<name>` branch in its AFK stretch, then parks: the park comment, `wayfinder:awaiting-human`, a park notice, and a thread message. For a prototype from the `prototype` skill, the message says how to open it and names the one question it answers. For an architecture prototype, the pending question is its first `architecture` round, and both the message and the park comment are that round in full, per **Rounds** and **Render the diagram** in `architecture`. Its branch stays empty until capture, so until then the thread message links only the ticket and the ticket comment has no links line. Each human reply is feedback. A `prototype` skill worker iterates, pushes, and ends its turn. An architecture worker posts its next round in the thread and as a new ticket comment, ends its turn, and pushes its branch at capture. The human's explicit acceptance is the only resolution. On acceptance, the worker pushes the branch, posts the durable handoff with the decision and the branch pointer, removes `wayfinder:awaiting-human`, closes the ticket, and notifies and settles.

**Spec, HITL task, ship, and successors.** The worker runs its AFK stretch with its prescribed skill, and a successor continues from its child's park, whose park comment and label already stand; a `ship` worker follows [`SHIP.md`](SHIP.md) and resolves without a park when its review leaves no decision open. Otherwise it parks: the park comment, `wayfinder:awaiting-human`, a park notice, and a thread message with the pending question and the ticket link. Each human reply answers it: the worker records the decision on the ticket and continues to the next park or to the resolution. On resolution, the worker posts the durable handoff, removes `wayfinder:awaiting-human`, closes the ticket, and notifies and settles.

## Notify and settle

Every worker prompt includes these steps. The worker sends a notice only on a tracker transition, never on an ordinary conversation turn:

- **First park** → after the park is durable, send the conductor `<type> #<id> parked` with `t3_thread_send`, `mode: auto`, to the `Conductor thread` in the map's **Notes**.
- **Closed** → after the ticket is closed, send the conductor `<type> #<id> closed` the same way. Then call `t3_thread_organize` with `action: settle` and no `threadId`. The thread settles when its turn ends and leaves the human's active list.

If the send fails, the worker still settles. The conductor finds the closed ticket at its next frontier query.

## Wait out of the inbox

While the conductor only waits for its lanes, it must not sit in the human's inbox. T3 keeps a thread on the Working shelf while its turn is over and a monitor, subagent, or background task it started still runs. A plain background command does not count: T3 treats it like a dev server left running and returns the thread to the inbox. The conductor uses one **hold** for this: a monitor that only sleeps. A hold reads no state and wakes no one but the conductor, so it is not a waiter or a poller.

A live child task holds the conductor on the Working shelf the same way, whatever the turn ends with. So the human meets each park in its own lane's thread, which reaches the inbox when its worker ends the turn per **leave nothing running** in [`SKILL.md`](SKILL.md).

The inbox means the human must act. End every conductor turn in one of two ways:

- **Nothing for the human to act on, and a lane is open** → exactly one hold runs. This includes a turn that ends with a message, such as a status update, a relayed result, or an answer to the human's question: the human reads it on the Working shelf. If no hold runs, start one before the turn ends. In Claude Code, start the Monitor tool with the command `sleep 1800` and `timeout_ms: 1800000`, the Monitor maximum. Do not use Bash with `run_in_background`, because T3 does not hold the thread for it.
- **The human must act**: a cue, a question, an orchestration blocker, or done → no hold runs. Stop the hold before the turn ends; in Claude Code, call `TaskStop` with its task id. The conductor then returns to the inbox, and the human sees the action. It stays there until its next wake. While an AFK child task is still live, the action waits on the Working shelf until that child ends, within its wall-time cap. When one turn has both a status update and an action, the action decides. A turn that ends while a conductor question or orchestration blocker is still unanswered counts as an action turn.

A hold that ends by itself is a conductor wake: run the lane health check below, then end the turn by the same rule. A hold does not survive a conductor resume. If the runtime has no monitor that outlives the turn, skip the hold; the conductor then waits in the inbox.

## Wake

A notice from a thread is a worker notification. Apply the **Wake law** to the tracker first, then act on the ticket:

- **Closed** → verify the durable handoff and the settle below. The thread retires itself.
- **Open, first `wayfinder:awaiting-human`** → cue the human once with the thread title and the pending question. Record the `t3` cue marker.
- **Open, any other state** → leave the thread alone.

A ticket that parks while its lane is a child task, found on the child's wake or by any tracker query, moves to a thread. Call `task_cancel` on the child whatever `task_status` reports: a parked child can still hold the conductor. Then start a successor per **Start a thread**. Its prompt carries the park comments, the child's `childThreadId` as the transcript, the branch the child pushed, and, for a ticket that runs code, the attach line from **Compute lease** in [`SKILL.md`](SKILL.md) while the map holds a lease, because the successor works in a new worktree. The successor restates the pending question in its thread, without a new park comment or re-asking answered ones, and sends the park notice. Cue that park, not the child's.

Whenever the conductor finds a T3 ticket closed, by notice or by a tracker query, it checks that `t3_thread_list` with `settled: true` lists the thread. If not, the notice or the settle failed: settle the thread with `t3_thread_organize`, `action: settle`, and its `threadId`.

On every conductor wake, including the end of a hold, first run `fleet lanes <map URL>` when the `fleet` CLI is available. It exits 1 and names each lane, thread or child task, on any devbox, that finished with its ticket open, stalled, waits on an approval nobody sees, or is gone; act on every line it prints. It judges a lane by its threads, so it outranks a task status of `waiting_for_children` or `cancelled`.

T3 thread lanes have no deadline wake. The human sees a stalled thread in the active list, and the lane contract's health check covers it: on each conductor wake, including the end of a hold, and before completion, run `kickoff status --thread <threadId>` for each open `Thread` lane whose last durable activity is older than 15 minutes.

- **`state` is `running` and `startedAt` is older than the cap** → `kickoff stop --thread <threadId>`, mark the lane orphaned, and reconcile per the lane contract.
- **`gone: true` with the ticket open** → the human archived or deleted the thread. Mark the lane orphaned, reconcile the ticket per the lane contract, and cue the human once to ask whether to redispatch it.
- **`kickoff status` fails twice** → the T3 server did not answer. Record an orchestration blocker on the map and cue the human once.

## Recovery

T3 threads survive a conductor resume. A ticket whose latest locator says `Runtime: T3 Code` recovers here, not through the runtime addendum.

Update `Conductor thread` in the map's **Notes** first. Then reconcile the tracker and run the lane health check above for each open `Thread` lane. For a `Task` locator, a parked ticket moves to a successor thread per **Wake**. Otherwise read `task_status`: a live task stays; a terminal one whose ticket is still open is orphaned, so reconcile it per the lane contract.

An invalidated ticket with a thread: record the invalidation, clear `wayfinder:awaiting-human`, `kickoff stop --thread <threadId>`, then settle the thread with `t3_thread_organize`, `action: settle`, and its `threadId`.
