# Build: issue

An **issue** is the plan for one stack: the problem, the decisions, and the slices. The human answers the architecture rounds, if any, then reads the plan once, and the build runs to pull requests.

1. **First steps.** For each `research` fact, run the `research` skill in a background worker. For `prototype`, run the `prototype` skill. Bring each result to the plan question in step 3 as a decision, the recommended pick first. For `architecture`, run the `architecture` skill, which runs its own rounds with the human before the issue. Done when every first step has a result.
2. **Write the issue** in the tracker the user's agent instructions name for plans, else in the code repository's issues: the problem in one paragraph, the destination, each decision with its recommended answer, the slices in merge order, and what is out of scope. Each slice is a thin vertical slice of at most about 400 changed production lines that a test proves. In a public repository, the issue keeps only public context; numbers, customer data, and private findings go to a private note that the issue names. Done when the issue exists and links every first-step result.
3. **Ask at the plan.** Ask one question with the issue link, the Start verdict line, every open decision with the recommended answer first, and the items of the kickoff intake of `full-stop` (its `INTAKE.md`) for the stack. Write the intake answers into the issue's `## Intake` section. Use the harness's question tool when it has one. Done when the human answered and the issue has its `## Intake` section.
4. **Build the slices.** Run the `full-stop` skill for the stack, with the issue's `## Intake` section in place of its own kickoff intake. It builds the slices the issue lists, in order, each pull request stacked on the one before it and linked to the issue. Tick each slice on the issue with its pull request. When the repository's agent instructions say to commit to the default branch, commit and push each slice there with the repository's checks, in place of `full-stop`.

Done when every slice has a pull request that passed the gate of `full-stop`, or is pushed where the repository's agent instructions say, and the issue lists them.
