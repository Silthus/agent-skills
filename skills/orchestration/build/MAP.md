# Build: map

A **map** is work too large for one stack: a conductor thread charts it into tickets and runs one worker per ticket.

1. **Propose the map.** Ask the human one question: the verdict line, the destination in one sentence, the `impact` Start verdict line, the acts the conductor will take on this yes (private chat search and native task creation), and the choice to chart a map or to cut the work down to an issue. Done when the human answered. When they choose the issue, read [ISSUE.md](ISSUE.md).
2. **Conduct it.** Run the `orchestration-wayfinder` skill as the conductor, with the request as the loose idea. The human's yes is the user request that skill asks for. Write the verdict line into the map's **Notes**, and each judged first step, so charting makes it a ticket. When this build began at a smaller size, its issue, or the one-off's request, becomes the map's destination, and the conductor charts its open pull requests as the first stack ticket.

Done when `orchestration-wayfinder` reports its map done.
