# Orchestration

Skills that plan and drive a large piece of work across many agent sessions.
`orchestration-wayfinder` is the core: it runs a whole [Wayfinder](https://github.com/mattpocock/skills/tree/main/skills/engineering/wayfinder) map from one session and dispatches one worker per ticket, and one per strand of a spec.

- **[orchestration-wayfinder](./orchestration-wayfinder/SKILL.md)**: Drive a Wayfinder map from planning through implementation. Workers resolve research, grilling, prototype, and implementation tickets; a spec builds as strands, one lane per set of slices that share files. Each spec ships as one reviewed draft pull request. Has addenda for Claude Code, Codex, and T3 Code. Type `/orchestration-wayfinder`, or ask an agent to conduct a map.
- **[t3-kickoff](./t3-kickoff/SKILL.md)**: Start, watch, archive, or delete [T3 Code](https://github.com/pingdotgg/t3code) threads from the command line, and hand the current work to another machine as a new T3 thread. Needs Bun and a running T3 server.
- **[impact](./impact/SKILL.md)**: Checks whether work moves the needle on a team goal. It names the objective and the metric, links where the team measures it, and pushes back on work that pays into no objective. Map charting and PR descriptions run it, and your agent instructions can run it before a PR starts. It reads the goals sources that your agent instructions name.
- **[usage-brief](./usage-brief/SKILL.md)**: Gathers how users and agents use a product surface before work changes it: reach, UI versus MCP and API use, interactions, paths and the call path, feedback, support tickets, errors, and replays, with flags such as muscle memory and agent contracts. Map charting runs it as a sweep, and UI prototypes run it for the controls they change. It reads the product analytics project that your agent instructions name; the source list is written for PostHog.
- **[architecture](./architecture/SKILL.md)**: Shape a change larger than one module in `grilling` rounds, one premise and one diagram per round, from the change map down to the contract at each seam. Looks for deepening opportunities in the modules the change touches, draws modules as frames with their seams and measured leaks from a JSON spec, and captures the locked design as Markdown and ADRs. Rendering the diagram needs Bun and a Chromium.

These skills build on Matt Pocock's skills: `wayfinder`, `grilling`, `domain-modeling`, `prototype`, `to-spec`, `to-tickets`, `research`, `tdd`, `handoff`, `retro`, and `codebase-design`. They also use `qa-swarm`, `merge-risk`, `babysit-pr`, and `pr-description` from [pull-requests](../pull-requests/README.md).
